# 코딩 컨벤션

기존 프로토타입 코드의 스타일을 기준으로 정리했다. 팀이 바꾸고 싶은 부분이 있으면 여기를 고치고 [[결정 기록]]에 남긴다.

## 이름

| 대상 | 규칙 | 예 |
|---|---|---|
| namespace | `ARES.<모듈>` (프로토타입은 `DungeonProto`) | `ARES.Rulebook` |
| 클래스·구조체·enum·메서드·프로퍼티 | PascalCase | `SafeZone`, `GetSurvivalRate()` |
| 인스펙터 노출 필드 | camelCase + `[SerializeField] private` | `[SerializeField] private float walkSpeed = 4f;` |
| private 필드 | camelCase | `currentDay` |
| 상수 | PascalCase | `const float DoorWidth = 2f;` |
| 인터페이스 | `I` + PascalCase | `IInteractable` |
| 용어 | [[용어집]]의 코드 식별자를 그대로 | 수칙서 → `Rulebook` |

- 외부에서 읽기만 하면 `public` 필드 대신 프로퍼티: `public float SurvivalRate { get; private set; }`
- 프로토타입은 편의상 `public` 필드를 쓰지만, 본 작업은 `[SerializeField] private`을 기본으로 한다.

## 주석
- 주석과 `/// <summary>`는 **한국어**.
- 클래스마다 "무엇을 하고 어디에 붙이는지" 한두 줄 요약을 단다 (프로토타입 코드 방식).
- 기획서의 특정 규칙을 구현한 부분은 근거를 적는다: `// 기획서 5장: 생존률 = (구조 + 자력 탈출) / 생성 수`
- 미정 사항을 임시 가정으로 구현했다면: `// TODO(P-07): 민간인 생존 판정 임시 규칙 — 미정 사항 참고`

## 인스펙터
- `[Header("...")]`로 묶고, 의미가 애매한 값엔 `[Tooltip("...")]`, 범위 값엔 `[Range]`.
- 밸런싱 대상 수치(속도, 확률, 주기)는 코드에 박지 말고 ScriptableObject나 인스펙터 값으로 뺀다.

## 구조 원칙
- **상태와 표현 분리:** 게임 규칙·상태(생존률, 수칙서, 설치물, Day)는 순수 C# 클래스나 매니저에 두고,
  MonoBehaviour는 입력·연출·표시를 맡는다. 멀티플레이 동기화가 쉬워진다.
- **데이터 주도:** 던전 종류, 엔티티, 수칙, 시설은 ScriptableObject로 정의해 기획자가 에디터에서 추가할 수 있게 한다.
- **결정적 생성:** 무작위 생성은 시드 기반 `System.Random`을 쓴다 (`UnityEngine.Random` 전역 상태 의존 금지). 영속화와 네트워크 동기화에 필요.
- **싱글톤 최소화:** 꼭 필요하면 한곳(예: `GameManager`)에서 참조를 모아 주입한다.
- 이벤트는 C# `event`/`Action`을 기본으로, 구독 해제(`OnDisable`)를 잊지 않는다.

## 성능
- `Update`에서 `GetComponent`, `Find`, LINQ, 문자열 조합, `new List` 금지 → 캐싱·재사용.
- 자주 생성·파괴되는 것(엔티티, 민간인, 이펙트)은 풀링.
- 물리 쿼리는 `NonAlloc` 버전 사용.

## 에디터 코드
- 에디터 전용 코드는 `Editor/` 폴더(또는 Editor asmdef)에. 런타임 파일 안에서는 `#if UNITY_EDITOR`로 감싼다.
- 반복 셋업 작업은 메뉴 아이템으로 자동화 (프로토타입 `EnemySetup`처럼).
