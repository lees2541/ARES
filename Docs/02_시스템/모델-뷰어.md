# 모델 뷰어 (에디터 도구)

## 목적

새로 만든 모델과 받아 온 애니메이션을 **씬을 만들지 않고 바로 확인**한다.
모델의 크기·리그·폴리곤 수를 보고, 애니메이션 클립이 그 모델에 맞는지 재생해서 본다.
게임 규칙을 구현하는 시스템이 아니라 제작을 돕는 에디터 도구다. 프로토타입과 본 작업 양쪽에서 쓴다 (PM 지시, 2026-11-28).

지금까지는 `Assets/Test/`에 확인용 씬을 그때그때 만들어 봤다. 그 방식을 대신한다.

## 쓰는 방법

- 메뉴 **Tools > ARES > Model Viewer** 로 창을 연다.
- 왼쪽 위 목록에서 모델을, 아래 목록에서 애니메이션을 누르면 오른쪽에 바로 재생된다.
- 프로젝트 창에서 모델이나 클립을 고르기만 해도 뷰어에 올라간다 ("프로젝트 창 선택 따라가기"가 켜져 있을 때).
  프로젝트 창에서 오른쪽 단추 > **ARES > Open in Model Viewer** 로도 연다.
- 미리보기: 왼쪽 끌기 = 돌리기, 오른쪽 끌기 = 옮기기, 휠 = 당기기. 아래 단추로 앞·옆·뒤·전체 보기.
- 재생 막대: 재생/멈춤, 시점 옮기기, 반복, 속도.
- 제자리: 켜면 제자리에서 재생한다(기본). 끄면 클립에 든 이동(루트 모션)대로 모델이 앞으로 나아가고, "따라가기"가 켜져 있으면 카메라가 따라간다.
- 보조 표시: 바닥 격자(한 칸 = 1 m), 키 기준(모델 옆에 세우는 기둥, 높이는 옆 칸에서 바꾼다).
- "그림 저장"은 지금 화면을 PNG 로 저장한다.

### 클립이 모델에 맞는지

| 클립 종류 | 재생되는 조건 |
|---|---|
| Humanoid (목록에 `H`) | 모델에 유효한 Humanoid 아바타가 있으면 뼈 이름이 달라도 재생된다 |
| Generic (`G`), Legacy (`L`) | 클립의 뼈 경로가 모델과 같아야 한다. 정보 칸에 "뼈 경로 일치 n%"로 나온다 |

- 맞지 않는 클립은 목록에서 흐리게 보인다. "맞는 것만"을 켜면 숨긴다. 기준은 뼈 경로 일치 50% (코드의 `CompatibleRatio`, 도구의 표시 기준일 뿐 게임 수치가 아니다).
- Mixamo 에서 받은 FBX 는 처음에 Generic 으로 들어와 Humanoid 모델에 맞지 않는다.
  그 클립을 고르면 **"이 클립 파일을 Humanoid 로 다시 임포트"** 단추가 나온다. 누르면 그 FBX 의 임포트 설정(Rig > Animation Type)만 바꾼다.
- 파일 이름에 `@`가 든 모델 파일(`X Bot@Walking.fbx`)은 애니메이션 파일로 보고, 프로젝트 창에서 고르면 모델이 아니라 클립으로 올린다 (Unity 의 이름 규칙).

### 정보 칸이 알려 주는 것

크기(가로·높이·깊이), 삼각형·정점·머티리얼·렌더러 수, 리그 종류와 뼈 수, 클립의 종류·길이·fps.
경고: 그릴 메쉬가 없음, 발바닥이 바닥(y=0)에서 2 cm 넘게 떨어짐, 뿌리 크기 값이 1이 아님, 클립이 모델에 맞지 않음.

## 구성 요소

| 클래스 | 역할 | 위치 |
|---|---|---|
| `ModelViewerWindow` | 창. 목록, 재생 막대, 정보 칸 | `Assets/ARES/Scripts/Editor/ModelViewer/` |
| `ModelViewerStage` | 무대. 열린 씬과 분리된 미리보기 공간에 모델을 세우고 그린다 (`PreviewRenderUtility`) | 같은 폴더 |
| `ModelViewerCatalog` | 모델·클립 찾기, 모델 재기, 클립과 모델의 뼈 경로 견주기 | 같은 폴더 |
| `ModelViewerCapture` | 창 없이 그림으로 굽는 진입점 | 같은 폴더 |

- 어셈블리: `ARES.Editor` (`Assets/ARES/Scripts/Editor/ARES.Editor.asmdef`, 이 도구를 만들면서 처음 만들었다).
- namespace: `ARES.EditorTools`. `ARES.Editor`로 하면 `ARES.*` 안에서 Unity 의 `Editor` 클래스를 쓸 때 이름이 충돌해서 피했다.
  프로토타입의 에디터 코드도 `DungeonProto.MapGen.EditorTools`를 쓴다. (AI가 제안했고 PM이 2026-11-28에 그대로 진행하게 했다)
- 화면은 IMGUI 로 만들었다. 프로젝트의 기존 에디터 코드가 모두 IMGUI 이고, 미리보기 도구도 IMGUI 용이다.
- 클립은 `AnimationClip.SampleAnimation`으로 한 시점씩 입힌다. 제자리 재생은 Animator 의 `applyRootMotion`을 꺼서 한다 (Animator 가 있는 모델에만 듣는다).
- 저장하는 데이터와 네트워크 동기화는 없다. 창의 선택과 설정은 창이 기억한다.

## 진입점 (다른 코드가 쓰는 방법)

```csharp
using ARES.EditorTools;

// 창을 열고 모델(과 클립)을 올린다.
ModelViewerWindow.Open(model, clip);

// 창 없이 그림으로 굽는다. 돌려받은 Texture2D 는 쓴 쪽이 DestroyImmediate 로 지운다.
Texture2D still = ModelViewerCapture.Render(model, clip, time: 0.5f, width: 512, height: 512, degreesFromFront: 25f);
Texture2D strip = ModelViewerCapture.RenderStrip(model, clip, frames: 6);   // 클립을 6 시점으로 나눠 이어 붙인 그림
ModelViewerCapture.SavePng(strip, "C:/somewhere/strip.png");
```

모델이나 애니메이션을 그림으로 확인하는 코드가 필요하면 새로 만들지 말고 `ModelViewerCapture`를 쓴다.
AI 도구가 모델을 확인할 때도 이 진입점을 Unity CLI 의 `script eval`로 부른다.

## 다른 시스템과의 관계

- 의존하는 것: Unity 에디터 API 뿐이다. 런타임 코드와 프로토타입 코드에 의존하지 않는다.
- 이 도구에 의존하는 것: 없음.

## 테스트 · 확인 방법

1. Tools > ARES > Model Viewer 를 연다.
2. 모델 목록에서 `Alien_Rebu_01`을 누른다. 정보 칸에 높이 1.00 m, 리그 "Humanoid (아바타 유효)"가 나오는지 본다.
3. 애니메이션 목록에서 `Walking`을 누른다. 걷는 동작이 반복 재생되는지 본다.
4. "키 기준"을 켜고 높이를 바꿔 본다. 앞·옆·뒤 단추와 마우스 조작을 해 본다.

2026-11-28에 확인한 것: 컴파일 통과, `ModelViewerCapture`로 구운 그림(모델, 걷기 클립 6 시점, 프로토타입 Civilian 모델)이 맞게 나옴,
창을 열고 모델과 클립을 올려도 콘솔에 오류가 없음.
**확인하지 못한 것: 창의 실제 모습과 마우스 조작.** AI가 화면을 볼 수 없었다. PM이 한 번 열어 봐야 한다.
